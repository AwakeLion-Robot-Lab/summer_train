# newvision L3 整车状态估计说明

L3 把 L2 的二维装甲板检测转换成世界系整车状态，数据流固定为：

```text
ArmorDetection[]
→ IPPE PnP（双候选）
→ 连续 yaw 重投影优化（位置保持 PnP）
→ camera→barrel→world
→ 单假设整车 EKF
→ 简单物理面匹配
→ TargetState[]
```

当前是一版容易阅读、容易调试、效果接近 `tongjiceshi` 的可用基线，支持：

- `FourArmorVehicle`：普通四板车辆，4 面、面间隔 90°，有两组半径和高度。
- `ThreeArmorOutpost`：三板前哨站，3 面、面间隔 120°，只有一组半径和高度。

基地（小/大）和未知类别直接忽略，不生成 L3 观测；二板平衡车辆暂不处理，
L4 也不在本轮范围内。使用 `record_capture` 生成的 AVI/TXT 回放验证 L2/L3、
显示装甲板标注并向 PlotJuggler 发布曲线的方法见
[L3 录制视频回放](../../docs/l3_video_replay.md)。

## 1. 这一版要解决什么

这一版的目标是提供一个可读、可调试、可复现的 L3 基线：每帧把 L2 检测先转成
世界系观测，再按 `robot_id` 分组交给各自的整车 EKF，最终输出每辆车的
`TargetState[]`。所有算法块都能从入口顺序读懂，同一份回放数据可以随时与
`tongjiceshi` 直接对比。

第一版有意暂缓：

- 六自由度 LM 精化；
- `[tx, ty, tz, yaw]` Gauss-Newton；
- Huber loss；
- yaw 不可信时的位置-only 更新；
- 多假设和全局最优一对一分配（当前为按代价贪心的一对一）；
- 正式像素协方差传播。

## 2. 建议阅读顺序

第一次阅读不要从 EKF 细节开始，按数据流看：

1. `include/l3_estimation/types.hpp`
   - 看输入输出数据、目标模型和 11 维状态顺序。
2. `config/l3_config.yaml`
   - 看所有可调参数及其单位。
3. `src/l3_estimation/config.cpp`
   - 看 YAML 如何变成 `L3Config`，以及哪些错误配置会被拒绝。
4. `src/l3_estimation/pnp_solver.cpp`
   - 看四角点如何得到相机系单板位姿。
5. `src/l3_estimation/yaw_optimizer.cpp`
   - 看如何固定 pitch 和 PnP 位置，连续优化 yaw 并比较像素误差。
6. `src/l3_estimation/ekf_tracker.cpp`
   - 先看 `initialize/predict/update`，再看 Jacobian 和协方差。
7. `src/l3_estimation/target_estimator.cpp`
   - 看上面模块如何串成每帧完整流程。
8. `tests/*l3*`、`tests/pnp_solver_smoke.cpp`、
   `tests/yaw_optimizer_smoke.cpp` 和 `tests/ekf_tracker_smoke.cpp`
   - 用合成测试理解每一块的预期行为。

主要算法块前都有简短中文注释，说明这一段的输入、目的或输出。

## 3. 输入和输出

### 3.1 输入

`TargetEstimator::update` 接收：

```cpp
std::vector<L2Perception::ArmorDetection>
FrameContext{timestamp, image_size}
```

四个角点的顺序必须为：

```text
左上 → 右上 → 右下 → 左下
```

检测类别到模型的映射由 `TargetEstimator` 内部完成：

- `Outpost`（类别 6）→ `ThreeArmorOutpost`；
- `Guard`/`Hero`/`Engineer`/`Infantry3..5`（类别 0~5）→ `FourArmorVehicle`；
- 基地（类别 7、8）和未知类别 → 忽略，不生成观测。

每个 `robot_id` 只对应一个 `EkfTracker`；同帧同车多块检测按关联代价从小到大
依次更新，几何约束开启时同一物理面最多使用一次。

构造 `TargetEstimator` 时还要提供：

- 相机内参和畸变；
- `T_barrel_camera`；
- 在图像时刻返回 `R_world_barrel` 的 `BarrelPoseProvider`；
- `L3Config`。

如果配置要求尺寸匹配，而实际图像尺寸与标定尺寸不同，L3 会直接拒绝本帧。

### 3.2 输出

L3 返回：

```cpp
std::vector<L3Estimation::TargetState>
```

一辆已创建的目标对应一个 `TargetState`。关键字段包括：

- `model` 和 `armor_count`；
- `tracker_state`；
- 世界系 `center`、`velocity`；
- `yaw`、`yaw_rate`；
- `radius`、`radius_offset`、`height_offset`；
- `timestamp` 和 `last_observation_time`；
- `updated_this_frame`；
- 重投影误差、NIS、关联面等质量指标。

## 4. 坐标系

### 4.1 相机坐标系

OpenCV 相机坐标系：

```text
x_camera：图像右方
y_camera：图像下方
z_camera：相机前方
```

### 4.2 barrel 和 world

barrel 与云台姿态坐标轴刚性对齐：

```text
x：前
y：左
z：上
```

`R_world_barrel` 表示 barrel 坐标中的向量旋转到 world。
world 是 IMU 稳定的局部世界系，不是赛场绝对地图坐标系。

位置变换固定为：

```cpp
p_barrel = T_barrel_camera * p_camera;
p_world  = R_world_barrel * p_barrel;
```

命名规则：

```text
T_A_B：把 B 坐标中的点变换到 A 坐标
```

因此这里必须叫 `T_barrel_camera`，不能与 `T_camera_barrel` 混用。

### 4.3 装甲局部坐标系和 yaw

装甲局部坐标系：

```text
x_armor：装甲板法向
y_armor：装甲板左方
z_armor：装甲板上方
```

世界系 yaw：

```text
yaw = 0：法向指向 world +x
yaw > 0：从 +x 转向 +y
范围：(-pi, pi]
单位：rad
```

固定 pitch 姿态模型为：

```text
R_world_armor = Rz(yaw) * Ry(configured_pitch)
```

### 4.4 单位

```text
位置、半径、外参平移：m
线速度：m/s
角度：rad
角速度：rad/s
时间差：s
重投影误差：pixel
```

`pitch_rad` 必须填写弧度，例如：

```text
+15° = +0.2617993878 rad
-15° = -0.2617993878 rad
```

## 5. 第一版算法

### 5.1 IPPE PnP 与双候选

`PnpSolver` 默认使用 `solvePnPGeneric` 保留 OpenCV 返回的两个 IPPE 候选：

```cpp
cv::solvePnPGeneric(..., rvecs, tvecs, false, cv::SOLVEPNP_IPPE)
```

近正视目标的两个候选都可能通过几何检查（镜像歧义）。选解分两种：

- 已确认目标（`Tracking`/`TemporaryLost` 且已预测到当前帧）：用 Tracker 预测的
  整车 yaw 推算各物理面 yaw，选 raw yaw 最接近预测 face yaw 的候选（角距离须小于
  半个面间隔），只对该候选做 yaw 搜索；预测不可信时回退误差选解。
- 新目标、`Detecting` 或开关关闭时：每个候选都做固定 pitch 的 yaw 搜索，选优化
  重投影误差更小的候选。

因此下游始终是每块检测一个观测。配置 `pnp.enable_ippe_dual_candidates=false`
恢复旧 `cv::solvePnP` 单候选路径，`pnp.enable_predicted_face_yaw_selection=false`
关闭预测选解；回放可用 `--no-ippe-dual-candidates` 和
`--no-predicted-face-yaw-selection` 等价关闭，用于同数据 A/B。

每个候选执行相同检查：

- 角点必须有限；
- 四边形必须凸且面积足够；
- PnP 必须成功；
- `rvec/tvec` 必须有限；
- 距离必须在配置范围内；
- 装甲中心和四个角点都必须在相机前方；
- 四个角点的二维 RMSE 必须小于 PnP 门限。

这里的 PnP 重投影误差用于判断“这个单板位姿本身是否合理”。

### 5.2 连续 yaw 重投影优化

这一版用 Gauss-Newton 连续优化 yaw，替换原来的 1° 固定步长遍历。

步骤：

1. 从 PnP 旋转和坐标链计算 `yaw_raw_world` 作为初值。
2. 固定 PnP 的 `tvec` 和模型 pitch，参数 θ 只有 yaw 一个分量。
3. 每轮用数值雅可比（yaw 加一个有限差分步长）计算 8 维残差导数。
4. 解一维正规方程得到 yaw 更新量，投影非法或代价不下降时停在当前最优。
5. 达到 `max_iterations` 或更新量小于 `convergence_tolerance` 时结束。

优化后的位置仍取 PnP `tvec`，位置精化留到升级第 5 项（Huber loss 和阻尼）
接入后再开放；在回放数据上，位置精化会明显改变 EKF 的半径几何估计，因此在
无真值标定前保持位置不变。

yaw 优化误差不直接丢弃观测。原因是固定 pitch 与真实装甲安装角存在偏差时，
约束模型的像素误差可能很大，但 PnP 位置仍然可用。只有 PnP 原始 yaw 的重投影
本身非法（或最优误差非有限值）时才拒绝该观测；优化不改进时保留原始 yaw 的结果。

输出诊断：

```text
rpy_raw_world              # [roll, pitch, yaw]，PnP 原始世界系姿态
rpy_constrained_world      # [0, configured_pitch, optimized_yaw]
yaw_raw_world
yaw_world
pnp_reprojection_error_px
raw_yaw_reprojection_error_px
optimized_reprojection_error_px
```

### 5.3 camera→barrel→world

PnP 的 `tvec` 是装甲中心在 camera 中的位置。`TargetEstimator` 依次执行：

```text
position_camera
→ T_barrel_camera
→ position_barrel
→ R_world_barrel
→ position_world
```

yaw 搜索内部也使用同一旋转链，避免位置和姿态采用不同坐标定义。

### 5.4 11 维整车 EKF

状态顺序固定为：

```text
[xc, vx,
 yc, vy,
 zc, vz,
 yaw, yaw_rate,
 radius,
 radius_offset,
 height_offset]
```

观测固定为：

```text
z = [armor_x_world, armor_y_world, armor_z_world, armor_yaw_world]
```

预测模型：

```text
center += velocity * dt
yaw    += yaw_rate * dt
```

位置和 yaw 使用分段白噪声加速度模型；几何量使用很小的随机游走。
EKF 更新使用 Joseph 形式保持协方差数值稳定，yaw 创新始终归一化到
`(-pi, pi]`。

NIS 在第一版中只记录，不参与拒绝或复杂分配。

### 5.5 物理面匹配

第 `face_id` 个装甲面的预测 yaw：

```text
face_yaw = vehicle_yaw + face_id * face_interval
```

预测装甲位置：

```text
armor_x = center_x - radius * cos(face_yaw)
armor_y = center_y - radius * sin(face_yaw)
armor_z = center_z + height_offset
```

四板车的 1、3 号面使用第二组半径和高度。前哨站不使用第二组。

关联候选同时检查位置、yaw 和半径误差。候选观测沿预测装甲法向反推半径，要求
半径处于安全范围、与对应半径组的误差通过门限，并加入关联代价。同一帧使用按代价
贪心的一对一约束：一块观测和一个物理面都最多使用一次。

四装甲车辆允许 `r1 == r2`，此时俯视轮廓为正方形。允许两组半径不等，但四个装甲
中心依次连成四边形的最小内角必须满足：

```text
minimum_angle = 2 * atan2(min(r1, r2), max(r1, r2))
minimum_angle >= configured_limit
```

当前门限为 50°。该约束既用于关联候选门控，也用于 EKF 后验状态合法性检查；违反
约束的更新直接拒绝，不对状态和协方差做不一致的强行裁剪。

`tracker.enable_vehicle_geometry_constraints=false` 时关闭半径门控、最小内角检查和
物理面一对一限制，恢复每块观测仅按位置+yaw独立关联的基线行为，用于离线 A/B。

### 5.6 前哨站约束

前哨站仍复用 11 维状态，方便保持统一接口，但始终固定：

```text
radius_offset = 0
height_offset = 0
```

这两个状态对应的过程噪声、观测 Jacobian 和协方差行列也保持为零。

### 5.7 生命周期

```text
Lost → Detecting → Tracking → TemporaryLost → Lost
```

- 首次观测创建 `Detecting`。
- 连续命中达到 `confirmation_hits` 后进入 `Tracking`。
- 已确认目标短时无观测时进入 `TemporaryLost`。
- 超过模型自己的 `expiration_timeout` 后删除。
- Detecting 阶段漏一帧直接失败，下一次重新建立。

生命周期在整帧更新结束后统一改变，因此正常有观测帧不会产生假的
`Tracking→TemporaryLost→Tracking`。

## 6. 配置文件

统一配置位于：

```text
config/l3_config.yaml
```

主要分组：

- `armor`：装甲尺寸，以及普通车辆/前哨站独立 pitch、半径、过程噪声和超时。
- `pnp`：面积、距离和 PnP 重投影 RMSE 门限。
- `yaw_optimization`：连续 yaw 优化参数（迭代数、有限差分步长、收敛容差）。
- `observation_noise`：四维 EKF 观测噪声。
- `association`：位置/yaw/半径门限、权重和 NIS 参考值。
- `lifecycle`：确认帧数和最大预测间隔。
- `tracker`：11 维初始方差、半径范围和四装甲最小内角等几何安全范围。

`config.cpp` 对必需字段、版本、类型、单位范围和数值有限性进行集中校验。
缺字段或范围错误时抛异常，不允许带着半套默认值运行。

yaml-cpp 不解析表达式，`pitch_rad`、`parameter_step` 等数值字段必须写十进制
数值；`15 *3.141592653589793/180` 这类写法会在加载时直接报 `bad conversion`。

## 7. 调试接口

`TargetEstimator` 除返回 `TargetState[]` 外，还保留：

```cpp
lastObservations()
lastAssociationDiagnostics()
```

可查看：

- PnP 与 yaw 重投影误差；
- raw/optimized yaw；
- 关联物理面；
- 位置/yaw 匹配误差；
- innovation 和 NIS；
- 是否接受；
- 生命周期变化。

这些字段用于回放调参，不影响 L4 接口。

## 8. 当前验证结果

合成 smoke test 已覆盖：

- IPPE 双候选 PnP 和异常输入；
- `±pi` 附近的 yaw 搜索；
- 四板车辆初始化、预测、关联、几何约束和生命周期；
- 前哨站三面模型及 offset 锁零；
- `FrameContext` 图像尺寸检查；
- 普通车辆和前哨站独立配置。
- 几何约束开启/关闭两种关联路径的 A/B 行为。

`pnp_solver_smoke`、`yaw_optimizer_smoke`、`ekf_tracker_smoke` 和
`l3_baseline_smoke` 在 2026-08-07 全部通过。

真实回放（`recorder/3m_run_fast` 帧 0..780，离线模式，几何约束开启）结果：

```text
processed frames: 781
frames with published targets: 777
连续 yaw 优化（位置保持 PnP）：min corner angle=81.35deg, processing FPS=33.89
```

功能指标与 1° 网格基线（777 帧发布、最小内角 81.29°）一致；FPS 差异在多次运行的
噪声范围内（本机单次回放 FPS 波动约 ±15%）。

说明：该录像从第 781 帧起文件损坏，可解码区间只有帧 0..780，因此回放必须加
`--end-index=780`；其余录像的损坏位置和可用区间见
[L3 录制视频回放](../../docs/l3_video_replay.md)。

这只是功能验证，不代表最终精度验收。接下来仍需：

1. 用完好录像跑完整长回放；
2. 与 `tongjiceshi` 在同一数据上导出中间量对比；
3. 实测标定普通车辆和前哨站 pitch；
4. 调位置/yaw 观测噪声、关联门限和生命周期；
5. 达到既定的精度与连续性验收指标。
