# L5 火控与控制输出

## 1. 职责

L5 位于 L4 规划之后、串口发送之前，负责：

- 检查火控配置、标定状态和工作模式；
- 检查 RobotState 和 Plan 是否过期；
- 检查目标、跟踪、弹道和射击窗口状态；
- 检查弹速、热量、云台机械范围和瞄准误差；
- 检查角度命令跳变和目标切换；
- 生成 `FireDecision`；
- 根据 Plan 和 FireDecision 生成 `SerialCommand`。

L5 不负责图像识别、PnP、EKF、目标运动预测和弹道求解，这些工作分别属于 L2、L3 和 L4。

当前调用链：

```text
L1 RobotState + L3 TargetState + L4 Plan
                    ↓
              FireEvaluator
                    ↓
              FireDecision
                    ↓
                Controller
                    ↓
              SerialCommand
                    ↓
              SerialWorker
                    ↓
                  下位机
```

## 2. 输入数据

### 2.1 L1 RobotState

`RobotState` 由下位机串口数据生成，L5 主要使用：

```cpp
struct RobotState {
  Orientation rpy;       // 当前云台姿态，rad
  double bullet_speed;   // 当前弹速，m/s
  double heat;           // 裁判系统当前射击热量 Q1
  EnemyColor enemy_color;
  WorkMode mode;
  TimePoint timestamp;   // 上位机收到并解析状态包的时间
};
```

当前 RPY、弹速、热量和模式共用一个 `timestamp`，没有独立的云台姿态时间戳。

### 2.2 L3 TargetState

`TargetState` 表示一辆敌方机器人的估计状态，主要包含：

```text
robot_id
center / velocity
yaw / yaw_rate
radius / radius_offset / height_offset
covariance
timestamp
```

`TargetState::timestamp` 表示这份目标状态在物理上对应的时刻。当前 Runtime 使用相机帧时间调用 TargetEstimator，因此它通常对应图像采集时间或 EKF 预测到的滤波时刻。

L5 当前只检查 `target` 是否存在，并用 `robot_id` 判断是否切换机器人，不直接检查 TargetState 的时间戳。

### 2.3 L4 Plan

L4 输出的 `Plan` 提供最终瞄准参考：

```cpp
struct Plan : AimReference {
  TimePoint generated_at;
  std::vector<AimSample> samples;
  bool using_MPC;
  bool ballistic_valid;
  bool fire_permitted;
  bool valid;
};
```

继承的 `AimReference` 主要包含：

```cpp
int target_id;
TimePoint impact_time;       // 预计弹丸命中目标的绝对时刻
bool tracking;
Eigen::Vector3d aim_point_barrel;
Eigen::Vector3d aim_point_world;
double yaw;
double pitch;
double fly_time;
```

普通模式使用 `plan.yaw/pitch`；MPC 模式使用 `plan.samples.front().yaw/pitch`。当 `using_MPC == true` 但 `samples` 为空时，按无效 Plan 处理。

### 2.4 FireInput

```cpp
struct FireInput {
  std::optional<L3Estimation::TargetState> target;
  L4Planning::Plan plan;
  L1Sensor::RobotState robot_state;
  TimePoint now;             // 本次 L5 判断时间
  bool calibration_ready;
};
```

## 3. 时间戳

各时间戳的含义：

```text
相机帧 timestamp          图像采集时间
TargetState::timestamp    目标状态对应时间
RobotState::timestamp     串口状态接收时间
Plan::generated_at        Plan 生成时间
FireInput::now            L5 判断时间
Plan::impact_time         预计命中时间
```

理想关系：

```text
TargetState::timestamp
    <= RobotState::timestamp
    <= Plan::generated_at
    <= FireInput::now
    < Plan::impact_time
```

当前 L5 检查：

```cpp
now - robot_state.timestamp <= max_robot_state_age
now - robot_state.timestamp <= max_gimbal_pose_age
now - plan.generated_at     <= max_plan_age
```

当前限制：

- RobotState 和云台姿态共用一个时间戳；
- 尚未检查空时间戳和未来时间戳；
- 尚未检查 `impact_time > now`；
- L4 当前把 `plan.generated_at` 设置成 `robot_state.timestamp`，还不是真正的 Plan 生成完成时间。

## 4. FireConfig

YAML 中角度使用 degree，加载后统一转换为 rad。当前配置字段：

```cpp
struct FireConfig {
  bool shoot_enable;

  std::optional<double> bullet_diameter;
  std::optional<double> min_bullet_speed;
  std::optional<double> max_bullet_speed;
  std::optional<double> heat_limit;
  std::optional<double> heat_per_shot;

  std::optional<double> min_yaw;
  std::optional<double> max_yaw;
  std::optional<double> min_pitch;
  std::optional<double> max_pitch;

  std::optional<double> yaw_distance_boundary;
  std::optional<double> near_max_yaw_command_jump;
  std::optional<double> near_max_yaw_error;
  std::optional<double> far_max_yaw_command_jump;
  std::optional<double> far_max_yaw_error;

  std::optional<double> max_aim_pitch_error;
  std::optional<double> max_pitch_command_jump;
  std::optional<double> max_pitch_error;

  std::chrono::milliseconds max_robot_state_age;
  std::chrono::milliseconds max_gimbal_pose_age;
  std::chrono::milliseconds max_plan_age;
};
```

当前 17 mm 基础配置：

```yaml
shoot_enable: false
bullet_diameter_m: 0.017
min_bullet_speed_mps: 10.0
max_bullet_speed_mps: 35.0
heat_limit: 260.0
heat_per_shot: 10.0
```

`parametersReady()` 要求所有必要数值存在、有限且范围合法。实车验收完成前必须保持 `shoot_enable: false`。

## 5. 开火判断流程

### 5.1 选择控制角度

```text
using_MPC == false
    → 使用 plan.yaw / plan.pitch

using_MPC == true 且 samples 非空
    → 使用 samples.front().yaw / pitch

using_MPC == true 且 samples 为空
    → command_valid = false
```

### 5.2 基础条件和数据可信度

当前依次检查：

- `FireConfig::parametersReady()`；
- `calibration_ready`；
- 工作模式不是 Idle；
- RobotState 是否超过 `max_robot_state_age`；
- 云台姿态是否超过 `max_gimbal_pose_age`；
- Plan 是否超过 `max_plan_age`；
- `plan.valid` 和 MPC 控制点；
- `target` 是否存在；
- `plan.tracking`；
- `plan.ballistic_valid`；
- `plan.fire_permitted`。

### 5.3 弹速

```cpp
min_bullet_speed <= robot_state.bullet_speed <= max_bullet_speed
```

超出范围时增加 `BadBulletSpeed`。

### 5.4 基础热量限制

根据规则，17 mm 每发增加 10 热量，42 mm 每发增加 100 热量。当前基础版本通过 `heat_per_shot` 预留下一发热量：

```cpp
predicted_heat = robot_state.heat + heat_per_shot;
heat_safe = predicted_heat <= heat_limit;
```

当 `heat_safe == false` 时：

- 增加 `HeatLimit`；
- `fire_feasible = false`；
- `shoot = false`。

17 mm、`heat_limit = 260` 的示例：

```text
Q1 = 245 → 预计 255 → 允许
Q1 = 250 → 预计 260 → 允许
Q1 = 251 → 预计 261 → 拒绝
```

当前热量实现的限制：

- Q0 来自 YAML 静态配置，不是下位机动态上报；
- 尚未记录连续射击中未反映到 Q1 的 pending heat；
- 尚未根据 10 Hz 规则在上位机估算冷却；
- 尚无实际发弹计数反馈。

因此当前版本适合基础单发保护。下位机仍应保留最终硬件热量保护。

### 5.5 机械范围和云台到位

机械范围：

```cpp
min_yaw <= command_yaw <= max_yaw
min_pitch <= command_pitch <= max_pitch
```

目标距离：

```cpp
target_distance = plan.aim_point_barrel.norm();
```

距离不超过 `yaw_distance_boundary` 时使用 near 阈值，否则使用 far 阈值。

云台到位误差：

```cpp
yaw_error   = abs(shortestAngle(command_yaw, actual_yaw));
pitch_error = abs(command_pitch - actual_pitch);
```

误差超过阈值时增加 `Unstable`。

### 5.6 命令跳变

当前命令与上一帧命令比较：

```cpp
abs(shortestAngle(command_yaw, last_command_yaw))
abs(command_pitch - last_command_pitch)
```

超过阈值时增加 `CommandJump`。

### 5.7 目标切换和稳定帧

当前通过 `robot_id` 判断目标机器人是否切换。切换时：

```cpp
stable_tracking_frames_ = 0;
last_switch_time_ = now;
```

目标存在、Plan 有效且处于 tracking 时增加稳定帧数。当前要求：

```cpp
stable_tracking_frames_ >= 2
```

当前限制：

- Plan 没有 `armor_id`，不能识别同一机器人内部的真实切板；
- `last_switch_time_` 尚未用于冷却时间；
- `last_fly_time_` 尚未用于弹道连续性判断；
- 同一个 Plan 被重复调用时仍可能重复增加稳定帧数。

## 6. FireDecision

```cpp
struct FireDecision {
  bool fire_feasible;
  bool shoot;
  std::vector<RejectReason> reasons;
};
```

最终逻辑：

```cpp
fire_feasible = heat_safe && reasons.empty();
shoot = heat_safe && fire_feasible && shoot_enable;
```

即：

```text
L4 fire_permitted
&& L5 所有本机安全条件
&& heat_safe
&& shoot_enable
→ shoot
```

`fire_feasible` 表示理论上是否满足开火窗口；`shoot` 是考虑总开关后的实际下发值。`shoot_enable == false` 时增加 `ShootDisabled`。

## 7. Controller 和串口输出

Controller 根据 Plan、FireDecision 和 RobotState 生成：

```cpp
struct SerialCommand {
  double yaw;
  double pitch;
  bool shoot;
};
```

规则：

```text
Plan 无效
    → 保持当前云台角度
    → shoot = false

Plan 有效且 using_MPC == false
    → 使用 plan.yaw / plan.pitch

Plan 有效且 using_MPC == true、samples 非空
    → 使用 samples.front().yaw / pitch

using_MPC == true、samples 为空
    → 保持当前云台角度
    → shoot = false
```

Controller 对最终 yaw/pitch 做有限数兜底。出现严重 Plan、时间、范围或命令跳变拒绝原因时，保持当前角度并关闭开火。

`SerialWorker::updateCommand()` 保存最新命令，发送线程按配置频率编码并发送给下位机。命令超时后保留最后角度，但强制 `shoot = false`。

## 8. RejectReason

当前主要拒绝原因：

```text
ShootDisabled          总开关关闭
ParametersNotReady     火控配置不完整
AutoAimDisabled        工作模式为 Idle
MissingCalibration     标定未就绪
RobotStateStale        机器人状态过期
GimbalPoseStale        云台姿态过期
PlanInvalid            Plan 无效、过期或 MPC 控制点缺失
NoTarget               没有目标
NotTracking            未跟踪
BallisticInvalid       弹道无效
OutsideHitWindow       不在 L4 射击窗口
BadBulletSpeed         弹速越界
HeatLimit              预计下一发后热量超过 Q0
OutOfRange             yaw/pitch 超出机械范围
CommandJump            控制命令跳变
ArmorSwitching         目标机器人发生切换
Unstable               稳定帧不足或云台未到位
NonFinite              预留原因，当前 FireEvaluator 尚未触发
```

## 9. 当前边界和后续工作

开启实车自动开火前，应完成：

1. 正确填写相机内参、畸变和外参；
2. 修正 L4 `Plan::generated_at` 的时间语义；
3. 在 L5 检查 `impact_time > now`；
4. 对空时间戳、未来时间戳和 NaN/Inf 做 fail-closed 检查；
5. 为 Plan 增加 `armor_id` 或唯一序号，完善切板和稳定帧判断；
6. 通过下位机发弹计数完善 pending heat；
7. 完成全项目编译、回放、台架和实车验收后再开启 `shoot_enable`。
