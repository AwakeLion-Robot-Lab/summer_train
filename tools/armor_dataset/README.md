# 装甲板数字数据工具

当前主要入口是 [旧贴纸数字测距](STICKER_DEPTH.md)：复用现有灯条精修和 PnP
生成同帧数字/距离伪标签，提供按录像划分的数据导出、训练和无 PnP 的学生推理入口。
这一流程仅处理旧贴纸，不混入点阵屏或仿真样本。

此前的参数化点阵仿真见 [SIMULATION.md](SIMULATION.md)。下面保留最初的字形合成工具说明。
视频、生成的数据集、训练权重及 Python 环境存放在本地忽略目录，不随源码上传。

## 点阵数字视频仿真数据集 v1

从用户提供的 `video/0f5dc6f28812fe3e82f634949caaf2e0.mp4` 提取真实发光字形，
用程序生成数字检测和分类数据。仅依赖 Python 3.9+、OpenCV 和 NumPy。

## 能从视频确认什么

- 视频为 576×1280、30 fps 的手机录屏，约 13.7 秒。
- 人工逐帧核对了红、蓝两种颜色的数字 1～7；`source_video.json` 保存 38 个模板帧的编号。
- 红色 6 只有一个清楚的模板帧，蓝色 6 只有两个。多个连续模板帧不算独立实物样本。
- 亮部可见点阵纹理，但没有可靠的实体装甲边框、屏幕四角、实际尺寸、像素间距或刷新频率。
- 数字不自动映射到兵种。尤其不能直接把显示的 6、7 当成本项目的 `ArmorClass` 下标。

模板提取限定在录屏中心 ROI，排除了右侧按钮、底部账号文字和顶部搜索框。
字形直接来自视频；没有用普通字体替代视频里的点阵数字，也没有生成未经观察的数字 0、8、9。
`reference/templates.jpg` 和每个原始裁剪可用于复核人工类别标注。

## 生成

在项目根目录执行：

```bash
python3 tools/armor_dataset/generate.py \
  --video video/0f5dc6f28812fe3e82f634949caaf2e0.mp4 \
  --output out/armor_digits_v1

python3 tools/armor_dataset/validate.py out/armor_digits_v1
```

默认生成 1400 张训练图、280 张合成验证图、280 张合成测试图，均为 640×640。
每 15 张有一张无目标负样本，其他图包含 1～4 个不重叠的字形。
目标请求高度为 20～135 像素，透视变换和旋转后外接框尺寸可能变化。
通过 `--train`、`--val`、`--test`、`--image-size`、`--seed` 调整数量、尺寸和随机种子。
输出目录必须为空，防止无意覆盖已有数据。相同输入、参数和依赖环境可复现。

变换包含：透视、旋转、水平压缩、曝光和颜色扰动、光晕、轻微失焦/运动模糊、
噪声、JPEG 压缩、轻度点缺失和行亮度变化。行亮度变化只是增强假设，不代表测得的 PWM 或刷新频率。
当前版本不生成遮挡/截断字形，避免把已经无法辨认的字形赋予确定身份。
默认背景是程序生成的暗场和简单几何杂物，不是真实赛场的照片级仿真。

可用 `--backgrounds /path/to/photos` 加入**确定没有目标数字的**背景照片。
照片按文件排序后分到三个互不重叠的集合；至少提供三张。
不要用含未标注数字或旧装甲数字的照片，以免制造漏标。
后续最好加入实际相机拍摄、无目标的赛场背景。

## 输出格式

```text
data.yaml                        YOLO 检测训练入口
classes.json                     检测/分类下标映射；兵种映射和物理关键点为空
images/{train,val,test}/*.jpg     640×640 RGB 场景（文件解码时 OpenCV 为 BGR）
labels/{train,val,test}/*.txt     class cx cy width height，坐标归一化
masks/{train,val,test}/*.png      uint8 字形实例掩码，0 为背景、1～4 为实例号
classification/{split}/{1..7,negative}/*.png
                                 64×64 三通道分类小图，等比例留边
manifest.jsonl                   每张图的实例、框、模板来源和变换参数
classification_manifest.jsonl    分类小图与父图、类别、颜色的对应关系
reference/                       模板原始裁剪、掩码、帧编号与配置
preview.jpg                      带检测框的合成样例
classification_preview.jpg       14 种颜色/数字组合的分类预览
summary.json                     数量、参数、依赖版本和源视频 SHA256
validation_report.json           独立校验结果，运行 validate.py 后生成
```

检测类别 0～6 为 `red_1`～`red_7`，7～13 为 `blue_1`～`blue_7`。
分类任务合并颜色，文件夹为 `1`～`7` 和 `negative`；按文件夹排序加载时下标为 0～7。
颜色仍保存在分类清单中，可以另行训练颜色分类。

**检测框表示发光数字的可见笔画范围，不是整块屏幕或装甲板的范围。**
掩码来自模板主颜色信号阈值（峰值的 30%）和几何变换，表示光学模糊前的字形支持区域，
不包含整圈光晕。框由掩码精确计算，不受随机背景的亮斑影响。
没有 YOLO Pose 标签；这些数字框不能直接接入目前依赖灯条端点的 PnP 和像素观测。

`data.yaml` 的 `path` 是生成目录的绝对路径。搬移或解压数据后应修改这一行。
验证程序会检查：图像/掩码/标签一一对应、YOLO 框与实例掩码的像素位置一致、
框不越界、类别和来源映射正确、分类小图尺寸与标签、每个集合的类别覆盖、
各集合无完全相同的检测图像，以及字形主颜色是否有足够信号。
它不等于人工审核或模型准确率评估。

## 训练和评估边界

这批数据用于数字检测/分类的预训练、接口开发和合成扰动实验。
所有集合使用同一段视频中的字形模板；不同随机种子、不同合成场景不能构成独立真实测试集。
合成验证/测试分数不能证明能识别未来正式装甲模块，也不能证明测距准确。
同样，数字检测准确率不能代替实体装甲定位精度。

拿到新实物后，应另采集不参与模板制作的真实录像，按录像/场景划分真实训练和测试集，
再验证外观迁移、远距离识别、显示切换和屏幕成像。
实体四角/尺寸明确后，才能增加对应的关键点数据和几何定位模型。
本次没有训练神经网络，也没有替换现有自瞄运行代码。
