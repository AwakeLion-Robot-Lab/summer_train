# 能量机关关键点抖动优化

2026-10-31 首版优化：在单帧内融合同一叶片的重复候选，并将检测结果与滤波投影
分别显示。工程 YAML 已开启融合；没有配置该选项时保持原来的 NMS 坐标。

## 实现

`OpenVinoKeypointDetector` 仍按原有门限筛选候选，按质量排序，在原图坐标中进行
跨类别 NMS，最后按大小符模式过滤。每个 NMS 组的原始获胜候选保持不变；
只融合它所属组中同一模型类别、至少三个共同可靠点且逐点几何一致的候选。
不同叶片、不同模型类别和关键点语义错位的候选不会参与融合。

质量为类别分数乘有效点平均置信度。支持候选的质量必须高于获胜候选的
`fusion_min_quality_ratio` 倍。几何门限取可靠靶板点最大间距乘
`fusion_max_point_distance_ratio`，下限 2 原图像素，上限为 NMS 距离。
质量和几何门限附近的权重连续衰减至零，逐点再乘该点置信度后加权平均。

获胜候选的类别、类别分数、逐点分数和有效性标记保留原值。弱点不贡献坐标，
获胜候选自身的弱点也不会被其他候选提升为有效点。NMS 使用融合前的中心，
因此融合不改变分组、类别筛选和检出数量。只有一份可靠候选时保留原坐标。
整个过程没有跨帧缓存、历史点插值或时间低通，不增加时间平滑造成的跟随延迟。

```yaml
rune:
  detector:
    fuse_keypoints: true
    fusion_min_quality_ratio: 0.8
    fusion_max_point_distance_ratio: 0.2
```

设 `fuse_keypoints: false` 可恢复原后处理坐标。质量比例范围为 `[0,1)`，几何比例
为 `(0,1]`，非有限值会被拒绝。本次保留类别门限 0.65、关键点门限 0.5、
最少三点、NMS 距离 30 原图像素和 `input_scale: 0.75`。

检测诊断新增 `fused=N`，表示实际贡献坐标的被抑制候选数，按最终输出组统计。
该计数不是新增目标数，也不是独立测量数。

实机和有标定、姿态的回放另画当前曝光时刻的滤波投影：青色十字圆环
`filtered R` 为符心，白色十字圆环 `filtered target` 为靶心。原有彩色五点显示
检测器输出，包括启用时的候选融合。没有当前帧滤波位姿、标定缺失或点在相机
后方时跳过滤波绘制；这个叠加层不参与估计与控制。

## 完整录像对照

同一 C++ 二进制依次运行关闭/开启融合配置，两种配置的模型、设备、输入尺度、
门限及录像均相同。关闭融合在第一段全部 1843 帧的坐标、类别和有效性标记，
与之前的 NMS 基线日志完全一致。

下表的小符/大符指本次调用的检测模式，并不替录像提供物理运行模式真值。

| 录像 / 检测模式 | 总帧数 | 关闭融合检出帧数 | 开启融合检出帧数 |
| --- | ---: | ---: | ---: |
| `2026-10-28_00-03-18.avi` / 小符 | 1843 | 1534 | 1534 |
| `2026-10-28_00-05-41.avi` / 大符 | 798 | 581 | 581 |

所有帧的检测数量均一致。对相邻两帧都检出完整未激活叶片、原靶心位移不超过
30 像素的帧对，用原图局部 ECC 配准估计实际图案运动：R 区域使用平移模型，
靶板区域使用仿射模型。仅保留相关系数至少 0.98 的配准，靶板额外要求仿射
尺度奇异值在 0.9～1.1 内。两种配置使用完全相同的帧对和配准变换。

测量指标为“下一帧检测坐标减去上一帧坐标经图像运动变换后的坐标”，因此包含
定位波动和配准误差。以下都是**图像运动补偿后的帧间残差**，不是人工标注的
绝对定位误差，不能单独证明无固定偏差、误检率下降或实弹命中率改善。

| 指标 / 原图像素 | 小符关闭 → 开启 | 大符关闭 → 开启 |
| --- | ---: | ---: |
| R 残差 P95 | 0.790 → **0.559** | 2.512 → **1.570** |
| R 残差 RMS | 0.392 → **0.284** | 1.227 → **0.838** |
| R 最大残差 | 2.627 → **1.480** | 5.572 → **3.639** |
| 靶心残差 P95 | 1.684 → **0.966** | 3.673 → **2.681** |
| 四个靶板点残差 P95 | 2.229 → **1.183** | 4.530 → **3.312** |
| 四个靶板点残差 RMS | 1.241 → **0.581** | 2.241 → **1.764** |

R 有效配准帧对分别为 1514、538；靶板分别为 1454、295（四点样本数为帧对数
乘四）。大符靶板变化更大，配准筛掉的样本较多，不能把保留样本上的改善外推
到未配准成功的帧。

融合没有消除所有局部波动。例如第二段第 397→398 帧，获胜候选自身的回归
已经发生突变，靶心残差从 7.635 变成 8.543 像素；大符四点最大残差从 10.234
变成 10.854 像素。整体 P95/RMS 改善不代表每一帧都改善。

同机顺序回放的检测平均耗时，小符关闭/开启为 14.87/15.16 ms，大符为
16.12/15.92 ms。这个单次结果不用于宣称速度改善；融合没有额外模型推理。

## 验证与复现

构建并通过 `rune_detector_smoke`、`rune_partial_keypoints_smoke`。新增回归覆盖：
候选得分互换时减少坐标突跳、同图重复结果一致、不同叶片和类别隔离、语义点
错位隔离、弱支持点不污染可靠点、弱获胜点不被提升、缩放补边后的源图坐标
一致性及非法参数。滤波绘制验证了相机外参投影、过期位姿、负深度和缺失标定。
`auto_aim`、大小符回放入口和 `rune_detect` 均构建通过。

第一段有配套姿态录像的完整链路回放，关闭/开启融合的状态计数均为
`no_detection=309`、`no_contour=1`、`motion_not_ready=1533`，
`found_frames=1533`、`fire_feasible_frames=0`。融合没有新增轮廓或位姿失败，
也没有解决已有的运动拟合未就绪问题。第二段缺少姿态，只进行了检测与图像
配准对照，没有合成姿态验证控制。

原始日志、两份只切换融合开关且禁用窗口/UDP 的配置、统计 JSON 保存在
`build/rune_jitter_optimization/`。可使用独立脚本比较 `rune_detect` 的完整日志：

```bash
python3 tools/rune/compare_keypoints.py \
  --video video/rune/2026-10-28_00-03-18.avi \
  --before build/rune_jitter_optimization/small_off.log \
  --after build/rune_jitter_optimization/small_on.log \
  --output build/rune_jitter_optimization/small_comparison.json
```

脚本依赖 Python OpenCV 和 NumPy。`rune_detect --frames 100000` 可读取到录像
结尾，每段配置分别运行一次并重定向日志，再使用该脚本统计。

本次落实单帧候选融合和滤波投影显示。R 点的独立轮廓/模板精定位尚未启用：
当前配置没有与真实符心定义对齐的 R 模板或实测轮廓，直接使用字母 R 的亮区
质心会引入未经验证的固定偏差。后续应在具有符心标注或实测模型的素材上评估。
