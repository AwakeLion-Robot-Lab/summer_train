读之前:两条约定

这两条如果搞反,后面所有符号都会读反。先钉死。

约定一 · 装甲板系的 x 轴指向车心,不是朝外

在 armor_pose() 里,第 i 块板的位置是 -r·(cos yaw, sin yaw),而姿态绕 z 轴转了 +yaw,于是旋转矩阵第一列(板的 x 轴)约等于 +(cos yaw, sin yaw)。

这两个方向恰好相反——板的 x 轴从板心指回车心。板的可见面是它的 −x 侧。这就是代码里到处写 front_normal = -axis_x 的原因。

约定二 · 角点顺序是 TL, BL, BR, TR
// type.hpp:50
enum ArmorKeyPointsIndex { LEFT_TOP, LEFT_BOTTOM, RIGHT_BOTTOM, RIGHT_TOP, N };

逆时针,从左上出发先往下走。newvision 用的是 TL, TR, BR, BL(顺时针),移植时必须重映射:

  • 左灯条 = newvision corners[0](TL)+ corners[3](BL)
  • 右灯条 = newvision corners[1](TR)+ corners[2](BR)
好消息 · 三维物点约定两边一致

两个项目的装甲板系都是 x = 板面法向,y = 左,z = 上,物点都是 (0, ±W/2, ±H/2)。相机光学系变换矩阵也一样,awakening 的 R_CV2PHYSICS 和 newvision CLAUDE.md 里记的 [[0,0,1],[-1,0,0],[0,-1,0]] 是同一个矩阵。这两块移植时不用动。

template<class T>

    Eigen::Matrix<T, 3, 3> W;
    W << T(0), -w.z(),  w.y(),
         w.z(),   T(0), -w.x(),
        -w.y(),  w.x(),   T(0);

}
数学笔记 · hat 算子

hat 算子 \(\wedge\) 把 \(\mathbb{R}^3\) 映到李代数 \(\mathfrak{so}(3)\)(3×3 反对称矩阵集合):

$$\boldsymbol\omega^\wedge = \begin{bmatrix}\omega_1\\\omega_2\\\omega_3\end{bmatrix}^\wedge = \begin{bmatrix}0 & -\omega_3 & \omega_2\\ \omega_3 & 0 & -\omega_1\\ -\omega_2 & \omega_1 & 0\end{bmatrix}$$

它的意义是把叉乘写成矩阵乘法:

$$\boldsymbol\omega^\wedge \mathbf{v} = \boldsymbol\omega \times \mathbf{v}$$

两条要背下来的性质,后面推导反复用:

$$(\boldsymbol\omega^\wedge)^\top = -\boldsymbol\omega^\wedge, \qquad (\boldsymbol\omega^\wedge)^3 = -\|\boldsymbol\omega\|^2\,\boldsymbol\omega^\wedge$$

第二条是罗德里格斯公式只有两项的根本原因——三次方能退回一次方,幂级数被截断。

指数映射:旋转向量 → 旋转矩阵。

template<class T>
inline Eigen::Matrix<T, 3, 3> so3_exp(const Eigen::Matrix<T, 3, 1>& phi) {
    const T theta2 = phi.squaredNorm();
    const T theta  = ceres::sqrt(theta2);        // 不是 std::sqrt

    const auto W  = so3_hat(phi);
    const auto W2 = W * W;

    Eigen::Matrix<T, 3, 3> R = Eigen::Matrix<T, 3, 3>::Identity();

    T A, B;
    if (theta2 < T(1e-12)) {                    // 小角度分支
        const T theta4 = theta2 * theta2;
        A = T(1)   - theta2 / T(6)  + theta4 / T(120);
        B = T(0.5) - theta2 / T(24) + theta4 / T(720);
    } else {
        A = ceres::sin(theta) / theta;
        B = (T(1) - ceres::cos(theta)) / theta2;
    }

    R += A * W + B * W2;
    return R;
}
数学笔记 · 罗德里格斯公式的推导

指数映射按定义是矩阵幂级数。令 \(\boldsymbol\phi = \theta\mathbf{a}\),其中 \(\theta = \|\boldsymbol\phi\|\) 是转角,\(\mathbf{a}\) 是单位转轴:

$$\exp(\boldsymbol\phi^\wedge) = \sum_{n=0}^{\infty} \frac{1}{n!}(\boldsymbol\phi^\wedge)^n = \mathbf{I} + \boldsymbol\phi^\wedge + \tfrac{1}{2!}(\boldsymbol\phi^\wedge)^2 + \tfrac{1}{3!}(\boldsymbol\phi^\wedge)^3 + \cdots$$

用上面那条 \((\mathbf{a}^\wedge)^3 = -\mathbf{a}^\wedge\)(单位向量),所有高次项都能塌回 \(\mathbf{a}^\wedge\) 和 \((\mathbf{a}^\wedge)^2\) 两项。按奇偶次分组:

$$\exp(\theta \mathbf{a}^\wedge) = \mathbf{I} + \underbrace{\left(\theta - \tfrac{\theta^3}{3!} + \tfrac{\theta^5}{5!} - \cdots\right)}_{\sin\theta}\mathbf{a}^\wedge + \underbrace{\left(\tfrac{\theta^2}{2!} - \tfrac{\theta^4}{4!} + \cdots\right)}_{1-\cos\theta}(\mathbf{a}^\wedge)^2$$

即罗德里格斯公式:

$$\mathbf{R} = \mathbf{I} + \sin\theta\,\mathbf{a}^\wedge + (1-\cos\theta)(\mathbf{a}^\wedge)^2$$

代码里存的是 \(\boldsymbol\phi\) 而不是 \((\theta, \mathbf{a})\),所以 \(\mathbf{a}^\wedge = \boldsymbol\phi^\wedge/\theta\),代入后:

$$\mathbf{R} = \mathbf{I} + \underbrace{\frac{\sin\theta}{\theta}}_{A}\,\boldsymbol\phi^\wedge + \underbrace{\frac{1-\cos\theta}{\theta^2}}_{B}\,(\boldsymbol\phi^\wedge)^2$$

这正是代码里的 A 和 B。

数学笔记 · 为什么必须有小角度分支

\(\theta \to 0\) 时 \(A = \sin\theta/\theta\) 是 \(0/0\),\(B = (1-\cos\theta)/\theta^2\) 也是 \(0/0\)。极限存在(分别是 1 和 1/2),但浮点直接算会得到 NaN。所以要用泰勒展开替代:

$$A = \frac{\sin\theta}{\theta} = 1 - \frac{\theta^2}{6} + \frac{\theta^4}{120} - \cdots$$
$$B = \frac{1-\cos\theta}{\theta^2} = \frac{1}{2} - \frac{\theta^2}{24} + \frac{\theta^4}{720} - \cdots$$

在误差状态滤波里,\(\boldsymbol\delta\) 永远接近 0,所以这条分支才是常走的路径,不是边界情况。

为什么是 ceres:: 而不是 std::

T 可能被实例化成 ceres::Jet<double,13>。std::sqrt 不认识 Jet,ceres::sqrt 通过 ADL 同时支持 double 和 Jet。整份代码模板化的原因就在这。

so3_log

对数映射:旋转矩阵 → 旋转向量。so3_exp 的逆。

template<class T>
inline Eigen::Matrix<T, 3, 1> so3_log(const Eigen::Matrix<T, 3, 3>& R) {
    const T cos_theta = (R.trace() - T(1.0)) * T(0.5);
    Eigen::Matrix<T, 3, 1> w;
    w << R(2,1) - R(1,2),
         R(0,2) - R(2,0),
         R(1,0) - R(0,1);

    if (cos_theta > T(1.0 - 1e-12)) {
        return T(0.5) * w;                       // θ→0 的极限
    }
    const T theta = ceres::acos(cos_theta);
    const T scale = theta / (T(2.0) * ceres::sin(theta));
    return scale * w;
}
数学笔记 · 从迹和反对称部分取回 φ

第一步,由迹取转角。对罗德里格斯公式取迹,注意 \(\mathrm{tr}(\mathbf{a}^\wedge)=0\)、\(\mathrm{tr}((\mathbf{a}^\wedge)^2)=-2\):

$$\mathrm{tr}(\mathbf{R}) = 3 + 0 - 2(1-\cos\theta) = 1 + 2\cos\theta$$
$$\Longrightarrow\quad \cos\theta = \frac{\mathrm{tr}(\mathbf{R}) - 1}{2}$$

第二步,由反对称部分取转轴。\((\mathbf{a}^\wedge)^2\) 是对称的,所以 \(\mathbf{R}\) 的反对称部分只来自中间那一项:

$$\mathbf{R} - \mathbf{R}^\top = 2\sin\theta\,\mathbf{a}^\wedge$$

代码里的 w 正是从 \(\mathbf{R}-\mathbf{R}^\top\) 里 vee 出来的向量,所以 \(\mathbf{w} = 2\sin\theta\cdot\mathbf{a}\),于是:

$$\boldsymbol\phi = \theta\,\mathbf{a} = \frac{\theta}{2\sin\theta}\,\mathbf{w}$$

这就是 scale = θ / (2·sin θ)。而 \(\theta \to 0\) 时 \(\theta/(2\sin\theta) \to 1/2\),对应那条早退分支 return 0.5 * w。

θ → π 没有保护

\(\theta \to \pi\) 时 \(\sin\theta \to 0\),scale 会爆。代码只保护了 \(\theta\to 0\) 那一端。

但这恰好是误差状态的价值所在。so3_log 只被用在两处:box_minus(算两个接近姿态之差)和 inject(注入一个小 \(\boldsymbol\delta\))。两处的输入都保证接近单位阵,永远碰不到 \(\pi\)。

反过来说:如果你把旋转当普通向量存在状态里直接加减,就一定会撞上这个奇异点。

数学笔记 · 为什么用 log 参数化

半径有硬性物理约束 \(r > 0\)。三种处理方式:

  • 不管 —— 滤波器可能把 \(r\) 推成负数,几何整个翻转
  • 每步 clamp —— 破坏协方差与状态的一致性(状态被投影了,\(\mathbf{P}\) 没有)
  • 重参数化为 \(\ell = \ln r\) —— \(\ell\in\mathbb{R}\) 无约束,\(r = e^\ell > 0\) 自动成立 ✔

代价是噪声要换算。由一阶传播:

$$\ell = \ln r \;\Longrightarrow\; \frac{\partial \ell}{\partial r} = \frac{1}{r} \;\Longrightarrow\; \sigma_\ell^2 \approx \frac{\sigma_r^2}{r^2}$$

这就是 process_noise() 里那行 q(LOG_R1,LOG_R1) = q_r / (r1*r1) 的来历(见 §7.2)。另一个副作用:log 参数化让半径的相对不确定性恒定——远处目标半径估不准,自动表现为更大的绝对方差。

template<typename T>
inline Eigen::Transform<T, 3, Eigen::Isometry>
armor_pose(const T x[X_N], int id, int armor_num, ArmorClass armor_number) {
    // ① 该板在车上的方位角 —— 纯几何常量，不是状态
    const T yaw = normalize_angle(T(id) * T(2.0 * M_PI / armor_num));

    const bool outpost = armor_number == ArmorClass::OUTPOST;
    const bool is_r2   = (armor_num == 4) && (id & 1);

    // ② 该板用哪一组半径 —— 状态量
    const T r = armor_radius(x, id, armor_num, armor_number);

    // ③ 板心在车体系的位置
    const T ax = -ceres::cos(yaw) * r;          // 注意负号
    const T ay = -ceres::sin(yaw) * r;
    T az = T(0);
    if (outpost) {
        if      (id == 1) az = x[idx::OUTPOST01DZ];
        else if (id == 2) az = x[idx::OUTPOST02DZ];
    } else {
        az = is_r2 ? x[idx::H] : T(0);
    }
    auto pose_in_car = Eigen::Transform<T, 3, Eigen::Isometry>::Identity();
    pose_in_car.translation() << ax, ay, az;

    // ④ 板在车体系的姿态：绕 z 转 yaw，再后仰 15°
    const T armor_pitch = outpost ? T(-FIFTTEN_DEGREE_RAD) : T(FIFTTEN_DEGREE_RAD);
    pose_in_car.linear() =
        utils::rpy2matrix(Eigen::Vector3<T>(T(0), armor_pitch, yaw), utils::RPYOrder::ZYX);

    // ⑤ 复合
    return whole_car_pose(x, armor_number) * pose_in_car;
}
数学笔记 · 结构先验如何进入模型

第 \(i\) 块板的方位角是常量,不是待估量:

$$\theta_i = \frac{2\pi i}{N}, \qquad N \in \{3, 4\}$$

板心在车体系的位置:

$$\mathbf{p}_i^{\text{car}} = \begin{bmatrix} -r_i\cos\theta_i \\ -r_i\sin\theta_i \\ \Delta z_i \end{bmatrix}, \qquad r_i = \exp(\ell_{1}\ \text{或}\ \ell_{2})$$

板在车体系的姿态,ZYX 欧拉角 \((0, \alpha, \theta_i)\),其中 \(\alpha = \pm 15°\):

$$\mathbf{R}_i^{\text{car}} = \mathbf{R}_z(\theta_i)\,\mathbf{R}_y(\alpha)$$

复合到世界系:

$$\mathbf{T}^{\text{odom}}_{\text{armor}_i} = \underbrace{\begin{bmatrix}\mathrm{Exp}(\boldsymbol\phi) & \mathbf{c}\\ \mathbf{0} & 1\end{bmatrix}}_{\text{整车，来自状态}} \cdot \underbrace{\begin{bmatrix}\mathbf{R}_i^{\text{car}} & \mathbf{p}_i^{\text{car}}\\ \mathbf{0} & 1\end{bmatrix}}_{\text{结构先验 + 两个状态}}$$

"装甲板跳变"在这里消失了。无论当前看到的是正面板、侧面板还是相邻板的一条灯条,它们都只是同一个 13 维状态在不同 \(i\) 上的确定性投影。只要能把观测关联到正确的 \(i\),它们就共同约束同一个状态向量——这就是"整车估计"相对"每块板各自滤波"的全部收益。

那个负号:板的 x 轴指向车心

位置是 \(-r(\cos\theta_i, \sin\theta_i)\),而 \(\mathbf{R}_z(\theta_i)\mathbf{R}_y(\alpha)\) 的第一列约等于 \(+(\cos\theta_i, \sin\theta_i)\cos\alpha\)。两者反向 —— 板的 x 轴从板心指回车心。

所以可见性判据要用 \(-\mathbf{a}_x\):

// armor_target.cpp:524  可见性打分

Vec3 front_normal = -axis_x;                                // 朝外那一面
score = front_normal.dot(-pose_in_camera_cv.translation()); // 越大越正对

数学笔记 · 先想清楚为什么需要它们

普通 EKF 的三个动作都假设状态住在向量空间:

$$\mathbf{x} \mathrel{+}= \mathbf{K}\mathbf{r}, \qquad \mathbf{P} = \mathbf{F}\mathbf{P}\mathbf{F}^\top + \mathbf{Q}, \qquad \mathbf{P} = \mathbb{E}[(\mathbf{x}-\bar{\mathbf{x}})(\mathbf{x}-\bar{\mathbf{x}})^\top]$$

旋转不住在向量空间,\(SO(3)\) 是流形。把旋转向量当普通向量加会出四种问题:

  • \(\boldsymbol\phi_1 + \boldsymbol\phi_2 \neq \mathrm{Log}(\mathrm{Exp}(\boldsymbol\phi_1)\mathrm{Exp}(\boldsymbol\phi_2))\) —— 差一个 BCH 修正
  • \(\|\boldsymbol\phi\|\to\pi\) 处 \(\mathrm{Log}\) 的雅可比发散,\(2\pi\) 处突变
  • 同一个物理姿态不确定性,在 \(\boldsymbol\phi\approx 0\) 和 \(\boldsymbol\phi\approx\pi\) 附近算出的 3×3 协方差完全不同
  • 直接对旋转向量分量求 \(\partial f/\partial \mathbf{x}\),差一个右雅可比 \(\mathbf{J}_r(\boldsymbol\phi)\)

解法:把状态劈成两半。

住在哪大小代码里
名义状态 \(\check{\mathbf{x}}\)流形上任意大x_nominal
误差状态 \(\boldsymbol\delta\)\(\check{\mathbf{x}}\) 处的切空间恒小,更新后归零delta_x

关键:滤波器的 \(\mathbf{P}\) 是 \(\boldsymbol\delta\) 的协方差,不是 \(\mathbf{x}\) 的。切空间是货真价实的向量空间,所有线性代数都合法;而 \(\boldsymbol\delta\) 恒在 0 附近,永远碰不到 \(\pi\) 的奇异点。

数学笔记 · ⊞ 的定义,以及为什么右乘

形式上:

$$\boxplus:\ \mathcal{M}\times\mathbb{R}^{13}\to\mathcal{M}, \qquad \check{\mathbf{x}}\boxplus\boldsymbol\delta = \begin{cases} x_i + \delta_i & i \notin \{\text{rot}\}\\[4pt] \mathbf{R}\cdot\mathrm{Exp}(\boldsymbol\delta_{\text{rot}}) & i \in \{\text{rot}\}\end{cases}$$

右乘 vs 左乘。两种扰动方式:

$$\underbrace{\mathbf{R}\,\mathrm{Exp}(\boldsymbol\delta)}_{\text{右乘 · 局部/体坐标系}} \qquad\text{vs}\qquad \underbrace{\mathrm{Exp}(\boldsymbol\delta)\,\mathbf{R}}_{\text{左乘 · 全局/世界系}}$$

右乘的含义是"这辆车绕自己的轴又转了一点",左乘是"整个世界绕世界轴转了一点"。两者通过伴随矩阵相联:

$$\mathrm{Exp}(\boldsymbol\delta_{\text{世界}})\,\mathbf{R} = \mathbf{R}\,\mathrm{Exp}(\mathbf{R}^\top\boldsymbol\delta_{\text{世界}}) \;\Longrightarrow\; \boldsymbol\delta_{\text{体}} = \mathbf{R}^\top\boldsymbol\delta_{\text{世界}}$$

选右乘不是审美,是被下游两处逼的:

  1. 过程噪声天然是体坐标系的。地面轮式车沿行进方向的加速度噪声远大于竖直方向(配置里 qxyz_common: [30, 30, 1])。\(\mathbf{Q}\) 只有在体系里表达才有物理意义,再旋到世界系:\(\mathbf{Q}_{\text{odom}} = \mathbf{R}\mathbf{Q}_{\text{body}}\mathbf{R}^\top\)。
  2. vyaw 是绕车体自身 z 轴的角速度。\(\mathbf{Q}\) 里 rot_z–vyaw 那个 2×2 常角加速度耦合块,只有在 yaw 误差也是体系的时候才自洽。

代码注释说得很直白:"这里将误差设计为相对自身的旋转误差,所以 q 就是相对自身的运动"(armor_target.cpp:312)。

实现细节

那个 for 循环跳过旋转三维,循环外再单独处理。这样写而不是"先全加再覆盖",是因为旋转分量参与加法会污染中间结果(state_rotation(nominal) 在循环后被调用,读的必须是未被误加的旋转)。

下一个函数 box_minus_state 反而用了"先全减再覆盖"的写法,因为那里的减法不影响后续读取。两个函数的写法不对称,不是笔误。

数学笔记 · 互逆性证明(第一个该写的单测)

定义:

$$\boxminus:\ \mathcal{M}\times\mathcal{M}\to\mathbb{R}^{13}, \qquad \mathbf{x}\boxminus\check{\mathbf{x}} = \begin{cases} x_i - \check{x}_i \\[4pt] \mathrm{Log}(\check{\mathbf{R}}^\top\mathbf{R})\end{cases}$$

要求的性质:

$$(\check{\mathbf{x}}\boxplus\boldsymbol\delta)\boxminus\check{\mathbf{x}} = \boldsymbol\delta \qquad\text{且}\qquad \check{\mathbf{x}}\boxplus(\mathbf{x}\boxminus\check{\mathbf{x}}) = \mathbf{x}$$

验证旋转部分(欧氏部分显然):

$$\mathrm{Log}\big(\check{\mathbf{R}}^\top(\check{\mathbf{R}}\,\mathrm{Exp}(\boldsymbol\delta))\big) = \mathrm{Log}\big((\check{\mathbf{R}}^\top\check{\mathbf{R}})\,\mathrm{Exp}(\boldsymbol\delta)\big) = \mathrm{Log}(\mathrm{Exp}(\boldsymbol\delta)) = \boldsymbol\delta \quad\checkmark$$

注意转置的位置必须和右乘配套。如果 ⊞ 用右乘而 ⊟ 写成 \(\mathrm{Log}(\mathbf{R}\check{\mathbf{R}}^\top)\)(左乘形式),互逆性就破了,而且不会报错——滤波器照样跑,只是雅可比全错、协方差没有意义、遇到大机动就发散。

所以第一个单测就写这个:随机生成 \(\check{\mathbf{x}}\) 和小 \(\boldsymbol\delta\),断言 \(\|(\check{\mathbf{x}}\boxplus\boldsymbol\delta)\boxminus\check{\mathbf{x}} - \boldsymbol\delta\| < 10^{-10}\)。它能抓住 90% 的符号/左右乘错误。

数学笔记 · 为什么不喂 PnP 位姿

传统做法:每块板 PnP 得到 \(\mathbf{z} = (x, y, z, \psi)\),当观测喂给滤波器。两个问题:

① PnP 误差高度各向异性且相关。共面四点、远距小目标、斜视角下,协方差的真实形状是:

$$\mathbf{R}_{\text{PnP}} = \begin{bmatrix} \sigma_x^2 & \cdot & \cdot & \cdot\\ \cdot & \sigma_y^2 & \cdot & \cdot \\ \cdot & \cdot & \sigma_d^2 & \rho\sigma_d\sigma_\psi \\ \cdot & \cdot & \rho\sigma_d\sigma_\psi & \sigma_\psi^2\end{bmatrix}, \qquad \sigma_d \sim 10\text{–}50\times\sigma_x,\ \ |\rho| \to 1$$

深度和 yaw 强相关,量级差一两个数量级。在滤波器里给它一个对角 \(\mathbf{R}\),就是在撒谎。

② PnP 是非线性优化的输出。它已经替你"决定"了姿态。再去滤它,是在滤一个被处理过的量——信息在 PnP 那一步就损失且被扭曲了。

UVL 的做法是把观测退回到更接近传感器原始输出的地方。像素误差近似各向同性,对角 \(\mathbf{R}\) 是个诚实得多的近似;而且一块板拆成两条灯条 = 8 个约束,比 PnP 吐出的 4 维多一倍。

inline void project_points_jets(
    const std::vector<cv::Point3f>& obj_pts,
    const Eigen::Transform<T, 3, Eigen::Isometry>& pose_cam,

    std::vector<Eigen::Matrix<T, 2, 1>>& img_pts_jet)

数学笔记 · 针孔 + Brown–Conrady

① 刚体变换到相机系:

$$\mathbf{P}^c = \mathbf{R}\,\mathbf{P}^w + \mathbf{t}$$

② 透视除法(归一化平面):

$$x_p = \frac{X^c}{Z^c}, \qquad y_p = \frac{Y^c}{Z^c}$$

③ 畸变。令 \(r^2 = x_p^2 + y_p^2\),径向 + 切向:

$$\begin{aligned} x_d &= x_p\underbrace{(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)}_{\text{径向}} + \underbrace{2p_1 x_p y_p + p_2(r^2 + 2x_p^2)}_{\text{切向}}\\ y_d &= y_p(1 + k_1 r^2 + k_2 r^4 + k_3 r^6) + p_1(r^2 + 2y_p^2) + 2p_2 x_p y_p \end{aligned}$$

④ 内参映射到像素:

$$u = f_x x_d + c_x, \qquad v = f_y y_d + c_y$$

整条链 \(\mathbf{P}^w \to (u,v)\) 是纯代数、处处可微(除了 \(Z^c = 0\)),所以 Jet 能一路穿过去,中心差分也能稳定工作。这是 UVL 观测模型可行的技术前提。

Zc ≤ 0 没有保护

板转到相机背面时 \(X^c/Z^c\) 会翻符号甚至除零,投影出一个荒谬的像素坐标,直接毒化 \(\mathbf{H}\) 和残差。

实践中靠上层的可见性筛选挡住(match_armor 里按法向排序只取前 3 块),但那是启发式,不是保证。移植到 newvision 时建议补一个 if (Zc < eps) return failure,并让观测被丢弃而不是被使用。

数学笔记 · 为什么是这四个量,而不是两个端点的四个坐标

维度一样是 4,信息量理论上也一样(是个可逆变换)。差别在误差结构。

设灯条上下端点的检测误差为 \(\boldsymbol\epsilon_{\text{top}}, \boldsymbol\epsilon_{\text{bot}}\)。真实的角点误差是各向异性的:沿灯条方向(纵向)的定位误差远大于垂直方向(横向),因为灯条两端是渐变的亮度衰减,而两侧是陡峭的边缘。记 \(\sigma_\parallel \gg \sigma_\perp\)。

如果用原始端点坐标 \(\mathbf{z} = (u_t, v_t, u_b, v_b)\):\(\sigma_\parallel\) 和 \(\sigma_\perp\) 会按灯条倾角混进每一个分量,\(\mathbf{R}\) 必须是稠密的、且随倾角变化。用对角 \(\mathbf{R}\) 就错了。

换成 \((\alpha, u_c, v_c, L)\) 之后,误差被自然分离:

分量定义主要吸收反映
L\(\|\Delta\|\)\(\sigma_\parallel\)(两端各一次)距离 / 尺度
u_c, v_c\((\mathbf{p}_t+\mathbf{p}_b)/2\)\(\sigma_\parallel\) 被平均掉一半位置
α\(\arctan(\Delta_x/\Delta_y)\)\(\sigma_\perp/L\)姿态

中心点尤其关键:纵向误差在两端反号时相消、同号时保留,取中点相当于做了一次平均,\(\sigma\) 降到 \(\sigma_\parallel/\sqrt{2}\)。而角度只受横向误差影响,且被灯条长度归一化:

$$\sigma_\alpha \approx \frac{\sqrt{2}\,\sigma_\perp}{L}$$

于是三类量可以各给各的 sigma,对角 \(\mathbf{R}\) 才成立。这正是配置里三个独立参数 r_sigma_px_by_length_ratio / r_sigma_length_by_length_ratio / r_sigma_angle 的由来。

atan2(Δx, Δy) —— x 在前,不是笔误

标准写法是 atan2(y, x) 量的是"偏离水平方向"的角。这里参数交换,量的是偏离竖直方向的角。

原因很实际:装甲板灯条基本竖直,\(|\Delta_y| \gg |\Delta_x|\)。用标准写法 \(\alpha\) 会在 \(\pm\pi/2\) 附近工作,残差归一化和线性化都别扭;交换之后 \(\alpha \approx 0\),干净得多。

数学笔记 · 误差状态转移矩阵 F

普通 EKF 里 \(\mathbf{F} = \partial f/\partial\mathbf{x}\)。ESEKF 要的是误差怎么传播:

$$\mathbf{F} = \frac{\partial \boldsymbol\delta^+}{\partial\boldsymbol\delta}$$

但 \(\boldsymbol\delta\) 和 \(\boldsymbol\delta^+\) 住在不同点的切空间(分别在 \(\check{\mathbf{x}}\) 和 \(f(\check{\mathbf{x}})\) 处),不能直接对状态求导。必须绕道名义状态:

$$\boldsymbol\delta \;\xrightarrow{\ \boxplus\ }\; \check{\mathbf{x}}\boxplus\boldsymbol\delta \;\xrightarrow{\ f\ }\; f(\check{\mathbf{x}}\boxplus\boldsymbol\delta) \;\xrightarrow{\ \boxminus\ }\; \boldsymbol\delta^+$$

于是:

$$\boxed{\;\mathbf{F} = \left.\frac{\partial}{\partial\boldsymbol\delta}\Big[\,f(\check{\mathbf{x}}\boxplus\boldsymbol\delta)\;\boxminus\;f(\check{\mathbf{x}})\,\Big]\right|_{\boldsymbol\delta=\mathbf{0}}\;}$$

代码就是这个式子的逐字实现,步骤 ②–⑥ 一一对应。链式法则由 Jet 自动完成——它把 \(\partial\boxplus/\partial\boldsymbol\delta\)、\(\partial f/\partial\mathbf{x}\)、\(\partial\boxminus/\partial\mathbf{x}\) 三段乘起来了。

如果偷懒直接对旋转向量分量求导会怎样?得到的是 \(\partial\boldsymbol\phi^+/\partial\boldsymbol\phi\),它与真正的 \(\mathbf{F}\) 相差右雅可比:

$$\mathbf{J}_r(\boldsymbol\phi) = \mathbf{I} - \frac{1-\cos\theta}{\theta^2}\boldsymbol\phi^\wedge + \frac{\theta-\sin\theta}{\theta^3}(\boldsymbol\phi^\wedge)^2$$

\(\boldsymbol\phi\approx 0\) 时 \(\mathbf{J}_r\approx\mathbf{I}\),差别看不出来;\(\|\boldsymbol\phi\|\) 一大就完全错,而且在 \(\pi\) 附近发散。ESEKF 的写法让你永远不必显式算 \(\mathbf{J}_r\)——它被吸收进 ⊞/⊟ 的自动微分里了。

delta_x = F * delta_x 是干什么的

正常流程里 delta_x 在每次 update 结束时被清零,所以这一行乘的是零向量,没有作用。它存在是为了支持"预测多次再更新一次"的用法——那种情况下上一次残留的误差状态也要跟着传播。

ArmorTarget 的用法是 predict/update 严格交替,所以这行实际是 no-op。

数学笔记 · 多观测拼接与信息累加

一帧里所有观测垂直拼接:

$$\mathbf{z} = \begin{bmatrix}\mathbf{z}_1\\\vdots\\\mathbf{z}_m\end{bmatrix},\quad \mathbf{H} = \begin{bmatrix}\mathbf{H}_1\\\vdots\\\mathbf{H}_m\end{bmatrix},\quad \mathbf{R} = \mathrm{blkdiag}(\mathbf{R}_1,\dots,\mathbf{R}_m)$$

一块完整板 = 2 条灯条 × 4 维 = 8 行;每条孤立灯条再加 4 行。

从信息形式看收益更清楚。后验信息矩阵是先验加上各观测的信息贡献:

$$\mathbf{P}_+^{-1} = \mathbf{P}_-^{-1} + \mathbf{H}^\top\mathbf{R}^{-1}\mathbf{H} = \mathbf{P}_-^{-1} + \sum_{k=1}^{m}\mathbf{H}_k^\top\mathbf{R}_k^{-1}\mathbf{H}_k$$

\(\mathbf{R}\) 块对角 ⟹ 信息严格相加。每多一个观测,后验不确定性单调下降。所以同时用装甲板和孤立灯条不是"多堆几个特征点",而是在滤波框架内给同一个整车状态增加独立约束。

数学笔记 · 中心差分求 H,以及为什么差 residual

要求的是 \(\mathbf{H} = \partial\mathbf{z}/\partial\boldsymbol\delta\),不是 \(\partial\mathbf{z}/\partial\mathbf{x}\)。所以扰动必须加在 \(\boldsymbol\delta\) 上再 ⊞ 进去:

$$\mathbf{H}_{:,i} \approx \frac{h(\check{\mathbf{x}}\boxplus(\boldsymbol\delta + \epsilon\mathbf{e}_i)) - h(\check{\mathbf{x}}\boxplus(\boldsymbol\delta - \epsilon\mathbf{e}_i))}{2\epsilon}$$

这一点错了(比如把 \(\epsilon\) 直接加在 \(\mathbf{x}\) 的旋转分量上),\(\mathbf{H}\) 和 \(\mathbf{P}\) 就不在同一个坐标系里,增益全废。

为什么差 residual 而不是 z_pred?因为 \(\mathbf{r} = \mathbf{z} - \hat{\mathbf{z}}\),\(\mathbf{z}\) 是常量,所以

$$\frac{\partial\mathbf{r}}{\partial\boldsymbol\delta} = -\frac{\partial\hat{\mathbf{z}}}{\partial\boldsymbol\delta} = -\mathbf{H} \;\Longrightarrow\; \mathbf{H} = -\frac{\partial\mathbf{r}}{\partial\boldsymbol\delta}$$

这解释了代码里的负号。而真正的动机是角度缠绕:如果直接差 \(\hat{\mathbf{z}}\),当 \(\hat{z}_\alpha^+\) 和 \(\hat{z}_\alpha^-\) 分别落在 \(\pm\pi\) 两侧时,差出来是 \(\approx 2\pi\) 而不是 \(\approx 0\),\(\mathbf{H}\) 的那一列会得到一个巨大的假梯度。走 residual 就吃到了 normalize_angle(§5.5)。

代价:每个观测 \(2\times 13 = 26\) 次完整投影。这是纯粹的工程妥协,不是理论需要——见下方。

数学笔记 · 迭代更新,以及此处偏离教科书之处

为什么迭代?标准 EKF 在先验点 \(\check{\mathbf{x}}\) 处线性化 \(h\)。先验偏得远时线性化点很糟,更新落错地方。迭代版每轮在当前估计处重新线性化,本质是对 MAP 目标做高斯牛顿:

$$\min_{\boldsymbol\delta}\ \underbrace{\|\boldsymbol\delta\|^2_{\mathbf{P}^{-1}}}_{\text{先验}} + \underbrace{\|\mathbf{z} - h(\check{\mathbf{x}}\boxplus\boldsymbol\delta)\|^2_{\mathbf{R}^{-1}}}_{\text{观测}}$$

对这条链路收益很大,因为 \(h\) 强非线性:透视除法 + 畸变多项式 + atan2 + sqrt。目标处在某些 yaw 上时,状态动一点投影出的灯条能扫过很大一片。

标准 IEKF 的迭代式(Bell & Cathey 形式):

$$\boldsymbol\delta_{k+1} = \mathbf{K}_k\big[\mathbf{r}_k + \mathbf{H}_k\boldsymbol\delta_k\big]$$

这份代码的写法:

$$\boldsymbol\delta_{k+1} = \boldsymbol\delta_k + \mathbf{K}_k\mathbf{r}_k$$

两者相差 \((\mathbf{I} - \mathbf{K}_k\mathbf{H}_k)\boldsymbol\delta_k\),而 \(\mathbf{K}\mathbf{H}\neq\mathbf{I}\),不等价。前者每轮都把 \(\boldsymbol\delta\) 重新锚回先验,后者是不断累加高斯牛顿步,理论上会偏离 MAP 解(先验项被反复计入)。

另外 \(\mathbf{P}_{\text{iter}}\) 在迭代中不更新,最后用最后一轮的 \(\mathbf{K}, \mathbf{H}\) 走 Joseph form。

这两处我没有实测过实际影响。移植时建议先按标准式实现,再和这一版对拍——如果差异可忽略就说明 \(\mathbf{K}\mathbf{H}\) 接近 0(观测信息远弱于先验),如果差异明显就说明这一版确实在过冲。

数学笔记 · Joseph form 为什么值得

标准形式 \(\mathbf{P}_+ = (\mathbf{I}-\mathbf{K}\mathbf{H})\mathbf{P}_-\) 只在 \(\mathbf{K}\) 恰为最优增益时成立,浮点误差会让 \(\mathbf{P}\) 失去对称性甚至正定性。Joseph form 对任意 \(\mathbf{K}\) 都成立:

$$\mathbf{P}_+ = (\mathbf{I}-\mathbf{K}\mathbf{H})\mathbf{P}_-(\mathbf{I}-\mathbf{K}\mathbf{H})^\top + \mathbf{K}\mathbf{R}\mathbf{K}^\top$$

右边是两个正定二次型之和,结构上保证半正定。在迭代 EKF 里 \(\mathbf{K}\) 本来就不是最优增益(它是最后一轮的),所以这里用 Joseph 不是可选优化而是必需。后面那行强制对称 0.5*(P+Pᵀ) 是再上一道保险。

数学笔记 · 从一块板反推整车

§2.6 给的是正向:

$$\mathbf{T}^{\text{odom}}_{\text{armor}_i} = \mathbf{T}^{\text{odom}}_{\text{car}}\cdot\mathbf{T}^{\text{car}}_{\text{armor}_i}$$

初始化时已知 \(\mathbf{T}^{\text{odom}}_{\text{armor}}\)(PnP 给的),想求 \(\mathbf{T}^{\text{odom}}_{\text{car}}\),于是右乘逆:

$$\mathbf{T}^{\text{odom}}_{\text{car}} = \mathbf{T}^{\text{odom}}_{\text{armor}}\cdot\big(\mathbf{T}^{\text{car}}_{\text{armor}}\big)^{-1}$$

但 \(\mathbf{T}^{\text{car}}_{\text{armor}}\) 依赖两个未知量:板编号 \(i\) 和半径 \(r\)。代码的处理是都用假设值:

  • 假设看到的是 0 号板(\(\theta_0 = 0\)),于是 \(\mathbf{p}^{\text{car}}_{\text{armor}} = (-r, 0, 0)^\top\),\(\mathbf{R}^{\text{car}}_{\text{armor}} = \mathbf{R}_y(\alpha)\)
  • 半径用经验先验 \(r_{\text{pre}}\)(常规车 0.26 m)

这两个假设都会错,但都不致命:

$$\text{编号假设错} \Longrightarrow \text{整车 yaw 偏 } \frac{2\pi k}{N}, \qquad \text{半径假设错} \Longrightarrow \text{车心沿视线偏 } \Delta r$$

因为编号只是标签的循环平移——把实际的 2 号板叫作 0 号,整个几何仍然自洽,只是整车 yaw 差 \(2\pi k/N\)。而 \(r\) 的偏差在后续观测中被修正(\(p_0[\text{LOG\_R1}] = 1\) 给了足够的不确定性)。真正不可观测的是 vyaw:单帧完全看不出车在不在转,所以 \(p_0 = 100\),等于告诉滤波器"这一维我基本不知道,请大胆用观测改它"。

jumped 标志的含义

jumped = false 表示"还没关联到过 0 号以外的板"。在这个状态下,整车 yaw、第二组半径 LOG_R2、高度差 H 几乎完全不可观测——只见过一块板,其余板的位置全靠初值猜。

所以 match_armor 用两套门限:armor_match_gate_not_all_init(宽松,让第二块板更容易进来)和 armor_match_gate(收敛后收紧)。newvision 的 TrackedTarget::jumped 语义完全一致,而且注释里写明了是粘滞的(一旦为真不再复位)。

Eigen::Matrix<double, X_N, X_N> ArmorTarget::process_noise(double dt) const noexcept {
    Vec3 q_xyz_body;  double q_yaw;
    if (target_number == ArmorClass::OUTPOST) {
        q_xyz_body = cfg.qxyz_output;  q_yaw = cfg.qyaw_output;   // 前哨：极小
    } else {
        q_xyz_body = cfg.qxyz_common;  q_yaw = cfg.qyaw_common;   // [30, 30, 1]
    }
    Eigen::Matrix<double, X_N, X_N> q;  q.setZero();
    const double dt2 = dt*dt, dt3 = dt2*dt, dt4 = dt2*dt2;

    // ① 平移：体系加速度噪声 → 旋到 odom
    const Mat3 car_in_odom_R = whole_car_pose(target_state.x.data(), target_number).linear();
    const Mat3 Q_acc_body = q_xyz_body.asDiagonal();
    const Mat3 Q_acc_odom = car_in_odom_R * Q_acc_body * car_in_odom_R.transpose();

    for (int i = 0; i < 3; ++i) for (int j = 0; j < 3; ++j) {
        q(pos_idx[i], pos_idx[j]) = 0.25 * dt4 * Q_acc_odom(i,j);
        q(pos_idx[i], vel_idx[j]) = 0.5  * dt3 * Q_acc_odom(i,j);
        q(vel_idx[i], pos_idx[j]) = 0.5  * dt3 * Q_acc_odom(i,j);
        q(vel_idx[i], vel_idx[j]) =        dt2 * Q_acc_odom(i,j);
    }

    // ② yaw：常角加速度模型，误差本来就在体系 → 不用旋转
    q(idx::VYAW,    idx::VYAW)    +=        dt2 * q_yaw;
    q(idx::C_ROT_Z, idx::VYAW)    += 0.5  * dt3 * q_yaw;
    q(idx::VYAW,    idx::C_ROT_Z) += 0.5  * dt3 * q_yaw;
    q(idx::C_ROT_Z, idx::C_ROT_Z) += 0.25 * dt4 * q_yaw;

    // ③ roll/pitch：随机游走，吸收地面坡度、外参残差
    const Mat3 Q_wpr_body = (Vec3(cfg.q_wpr, cfg.q_wpr, 0)).asDiagonal();
    for (int i = 0; i < 3; ++i) for (int j = 0; j < 3; ++j)
        q(rot_idx[i], rot_idx[j]) += dt * Q_wpr_body(i,j);

    // ④ 半径 / 高度：随机游走（log 状态要换算）
    q(idx::LOG_R1, idx::LOG_R1) = cfg.q_r / (target_state.r1() * target_state.r1());
    if (target_number == ArmorClass::OUTPOST) {
        q(idx::OUTPOST01DZ, idx::OUTPOST01DZ) = cfg.q_outpost_dz;
        q(idx::OUTPOST02DZ, idx::OUTPOST02DZ) = cfg.q_outpost_dz;
    } else {
        q(idx::LOG_R2, idx::LOG_R2) = cfg.q_r / (target_state.r2() * target_state.r2());
        q(idx::H, idx::H) = cfg.q_h;
    }
    return q;
}
数学笔记 · 常加速度模型的 Q 从哪来

把未建模的加速度当白噪声 \(a \sim \mathcal{N}(0, \sigma_a^2)\)。在 \(\Delta t\) 内它对位置和速度的影响:

$$\Delta p = \tfrac{1}{2}a\,\Delta t^2, \qquad \Delta v = a\,\Delta t \qquad\Longrightarrow\qquad \mathbf{G} = \begin{bmatrix}\tfrac{1}{2}\Delta t^2\\ \Delta t\end{bmatrix}$$

于是这个 2×2 块是:

$$\mathbf{Q}_{pv} = \mathbf{G}\,\sigma_a^2\,\mathbf{G}^\top = \sigma_a^2\begin{bmatrix}\tfrac{1}{4}\Delta t^4 & \tfrac{1}{2}\Delta t^3\\[3pt] \tfrac{1}{2}\Delta t^3 & \Delta t^2\end{bmatrix}$$

这就是代码里那四个系数 \(\tfrac14\Delta t^4,\ \tfrac12\Delta t^3,\ \tfrac12\Delta t^3,\ \Delta t^2\) 的来历,平移和 yaw 用的是同一套(yaw 那套是"常角加速度")。

数学笔记 · 为什么 Q 必须先在体系建再旋转

配置 qxyz_common: [30.0, 30.0, 1.0] —— 水平两轴 30,竖直轴 1,相差 30 倍。这个先验的物理含义是:

$$\mathbf{Q}^{\text{body}}_{a} = \mathrm{diag}(30,\ 30,\ 1)$$

"地面轮式车可以突然前后左右加速,但不会突然上下加速。"这句话只有在车体坐标系里才成立。车头朝东和朝北时,世界系下的噪声椭球方向完全不同。所以要旋转:

$$\mathbf{Q}^{\text{odom}}_{a} = \mathbf{R}^{\text{odom}}_{\text{car}}\,\mathbf{Q}^{\text{body}}_{a}\,\big(\mathbf{R}^{\text{odom}}_{\text{car}}\big)^\top$$

这是协方差在坐标变换下的标准传播律(\(\mathrm{Cov}(\mathbf{R}\mathbf{a}) = \mathbf{R}\,\mathrm{Cov}(\mathbf{a})\,\mathbf{R}^\top\))。

而 yaw 那一块不需要旋转,因为选了右乘之后误差状态本来就定义在体系里。代码注释:"这里将误差设计为相对自身的旋转误差,所以 q 就是相对自身的运动"。

如果当初选了左乘(世界系扰动),这里就得反过来把 yaw 噪声旋进世界系,而且 rot_z–vyaw 的耦合块会变成三维稠密的,因为"绕车体 z 轴"在世界系里是三个分量的组合。右乘的选择让这段代码保持简单。

数学笔记 · log 半径的噪声换算
$$q_{\ell\ell} = \frac{q_r}{r^2}$$

由 §2.4 的一阶传播 \(\sigma_\ell \approx \sigma_r / r\) 得到。直觉:配置里的 q_r 描述的是物理半径每秒能漂多少(米²),而状态存的是 \(\ln r\),所以要除以 \(r^2\) 换算到对数尺度。

副作用是大半径目标的对数噪声更小——基地(r≈0.32)比步兵(r≈0.26)的半径更"稳",符合直觉。

对 newvision 的启示

newvision 现在的 \(\mathbf{Q}\) 是直接在世界系给的对角阵。CLAUDE.md 里记着一个已知问题:"NIS near 0.12 against a 4-DOF expectation of 4 … 一个 sweep 显示 Q 主导了这个差距",而且降 Q 会让 3m_run_fast 变差 3.6 倍。

体系 Q + 旋转到世界系,很可能正是这个矛盾的出路:目前为了照顾机动目标只能整体抬高 Q,而体系 Q 允许你"沿行进方向给大、竖直方向给小",在不牺牲机动响应的前提下降低总的协方差膨胀。这是移植时值得优先验证的一项。

数学笔记 · R 为什么正比于灯条长度

设角点检测误差在像素空间近似恒定 \(\sigma_{\text{px}}^{\,0}\)(网络回归精度不随距离变)。那为什么 \(\sigma\) 还要乘 \(L\)?

因为我们关心的不是像素误差本身,而是它折算到状态空间的影响。灯条长度 \(L\) 与距离 \(d\) 成反比:

$$L \approx \frac{f\,H_{\text{armor}}}{d} \qquad\Longrightarrow\qquad d \approx \frac{f\,H_{\text{armor}}}{L}$$

同样 1 像素的横向误差,在距离 \(d\) 处对应的物理横移是 \(d/f\) 米——远处放大得多。若把 \(\sigma\) 设成常数,滤波器会误以为远处观测和近处一样可信。

取 \(\sigma \propto L\) 相当于:

$$\sigma_{\text{px}} = \kappa L \propto \frac{1}{d} \qquad\Longrightarrow\qquad \sigma_{\text{物理}} = \sigma_{\text{px}}\cdot\frac{d}{f} \propto \text{常数}$$

也就是说,这个缩放让"物理尺度上的观测噪声"近似恒定,距离权重不用手调。这是 newvision docs/pnp_observation_noise_and_covariance.md 里那套完整协方差传播的一个廉价但方向正确的替代品。

那个 / 2.0:一块板被拆成两条灯条、信息量翻倍,所以每条的方差减半,总信息量与"把整块板当一个观测"相当。

被注释掉的一行,和 README 的 TODO
// sigma_angle *= std::cos(z(idx::UV_ANGLE));
//   越接近垂直上下点的垂直灯条方向偏移越大，这个实际还是需要考虑遮挡模型

作者知道 \(\sigma_\alpha\) 应该随灯条倾角变化(灯条越斜,端点定位对角度的影响越大),但没有遮挡模型支撑,就先按住了。对应 README TODO 里的 "针对现实装甲板特征可见性的投影模型",以及那个 1 行空文件 armor_obstruction_model.hpp。
