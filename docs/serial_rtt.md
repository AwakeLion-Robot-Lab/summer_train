# 上位机 ↔ 下位机串口 RTT 测试

这个测试测量一条 Ping 从上位机开始写串口，到收到对应 Pong 完整帧的往返时间。它包含上位机串口库、USB/串口传输、下位机接收和回包排队时间；不包含云台机械响应。上位机工具不发送现有的 `0x0001` 控制命令，也不会请求开火。

## 双方约定的测试帧

沿用本项目串口帧格式，均为小端序、8N1。Ping 和 Pong 均为 13 字节，只有 `cmd_id` 不同：

| 偏移 | 长度 | 字段 | Ping | Pong |
| --- | ---: | --- | --- | --- |
| 0 | 1 | SOF | `A0` | `A0` |
| 1 | 2 | payload 长度 | `04 00` | `04 00` |
| 3 | 1 | 帧头 seq | 上位机逐帧递增 | 下位机自己的发送序号 |
| 4 | 1 | CRC8 | 对偏移 0～3 计算 | 同左 |
| 5 | 2 | cmd_id | `01 7F` (`0x7F01`) | `02 7F` (`0x7F02`) |
| 7 | 4 | `token` | 上位机给出的 `uint32_t` | 原样回显 |
| 11 | 2 | CRC16 | 对偏移 0～10 计算 | 同左 |

`token` 是**唯一配对依据**。帧头 `seq` 属于各自方向的总帧计数，Pong 的 seq 不必等于 Ping 的 seq。下位机若同时发送状态帧，Pong 也要使用同一套下位机 TX seq 计数器，不要单独复制 Ping 的 seq。正式接入前请确认 `0x7F01`、`0x7F02` 在下位机固件中未被占用。

CRC 与现有上位机 `SerialProtocol` 完全一致：CRC8 初值 `0xFF`，逐位右移、反射多项式 `0x8C`；CRC16 初值 `0xFFFF`，逐位右移、反射多项式 `0x8408`。CRC16 低字节先发送，无最终异或。

双方可先用这个向量互验（示例两帧的帧头 seq 均取 0，`token=0x01020304`）：

```text
Ping: A0 04 00 00 DC 01 7F 04 03 02 01 FB B1
Pong: A0 04 00 00 DC 02 7F 04 03 02 01 86 BD
```

## 下位机：最小改动

在现有串口解包流程中，**通过长度、CRC8、CRC16 校验后**处理 `cmd_id=0x7F01` 且 `payload_len=4` 的帧：

```c
// 在已有帧解析器确认整帧合法后调用；示意代码，发送 API 按固件替换。
if (cmd_id == 0x7F01 && payload_len == 4) {
    uint8_t token[4] = {payload[0], payload[1], payload[2], payload[3]};
    // 使用固件已有的帧封装/CRC 函数；TX seq 从下位机总发送序号分配。
    send_frame(0x7F02, token, 4);
    return; // 不修改电机目标、模式或开火状态
}
```

收到完整 Ping 后尽快回包。若回包必须进发送队列，请记录该队列等待时间，因为它会计入 RTT。不要用周期状态帧代替 Pong，也不要在 Ping 处理处等待控制任务。现有 `0x0001` 控制和 `0x0002` 状态帧格式不需要改动。

固件不在此仓库中，因此这部分需下位机同学在固件仓库实现。可先用上面的十六进制向量检查封装，再与上位机工具联调。

## 上位机：运行

先停止占用同一串口的 `auto_aim` 等程序，接好下位机，确认端口和波特率与固件一致：

```bash
xmake build serial_rtt
xmake run serial_rtt /dev/ttyACM0 115200 1000 20 100
```

参数顺序为 `[设备] [波特率] [次数] [发送间隔 ms] [单次超时 ms] [连续超时停止阈值]`；以上均为默认值。此版本 xmake 不需要参数分隔符 `--`；测试程序也兼容误加的 `--`。程序一次只等待一个 Pong，因此发送间隔小于实际 RTT 时，实际频率会自动降低。每 100 次输出一次进度；默认连续超时 10 次即提前停止并打印已测统计，避免固件停止回包后长时间无输出。最后一个参数设为 `0` 可关闭提前停止。没有收到任何合法 Pong 或提前停止时返回非零退出码。

输出包括 `received`、`timeout`、`unmatched_pong`、`bad_crc`，以及 RTT 的最小值、均值、P50、P95、P99、最大值，单位 ms。建议分别在**空闲**和**正常状态上报负载**下各跑一次，并记录端口、波特率、固件版本和结果。`timeout` 或 `unmatched_pong` 增长时，先查固件是否回显了 payload 中的 32 位 `token`，以及是否有旧回包或发送队列积压；`bad_crc` 增长时查帧格式、CRC 和链路误码。

### 只从上位机检查回包时机

已有 Ping/Pong 固件时，可以运行黑盒验证模式，不用改下位机：

```bash
xmake run serial_rtt verify /dev/ttyACM0 115200 100 20
```

最后两个参数分别是等待 Pong 的超时 `timeout_ms` 和故意留着半帧时的观察时间 `hold_ms`。测试依次检查：完整合法 Ping 有 Pong；仅发前 12 字节、扣住最后一个 CRC16 字节时没有 Pong；补发最后一字节后有 Pong；CRC16 故意改错的完整 Ping 没有 Pong；随后再发合法 Ping 仍有 Pong。每项会显示 `PASS`、`FAIL` 或 `INCONCLUSIVE`，只有全部通过才返回 0。

这能证明**这些测试帧**没有在接收完成前或 CRC 错误时触发回包，不能从上位机推断固件所有内部代码路径。若补发最后一字节后没有 Pong，常见原因是固件在 `hold_ms` 内清除了未完成的帧，此时显示 `INCONCLUSIVE`；可将 `hold_ms` 调小，例如 5 ms，再试一次。验证时也应独占串口。

上位机从 `write()` 调用前到 Pong 最后一个字节被读到计时，使用同一个 `steady_clock`，无需同步 MCU 时钟。115200 波特、8N1 下，两条 13 字节帧仅线上发送时间约 `26×10/115200 ≈ 2.26 ms`，实测值通常还包含 USB、调度和固件回包耗时。**RTT 除以 2 不能准确代表单向延迟**；若要测上位机发出到下位机执行，应在下位机执行点加时间戳并对齐时钟，或用示波器/逻辑分析仪测两端 GPIO。

当前主程序的 `delay/send_to_control` 是视觉控制链标定量，`pose_delay_ms` 是图像与姿态对齐补偿，都不等于本测试的串口 RTT。
