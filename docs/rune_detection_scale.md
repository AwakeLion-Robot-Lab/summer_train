# 能量机关输入尺度诊断

本文为五点严格筛选时期的尺度实验记录。当前检测已采用 SZU 官方至少三点的
筛选规则，最新配置及验证见 [SZU 后处理对齐](rune_szu_alignment.md)。

对 `video/rune/2026-10-28_00-03-18.avi` 的复查显示，模型对目标像素占比敏感，
缩小目标比单纯降低类别门限更有效。原图 `1440x1080`，模型输入固定 `640x480`；
颜色顺序、归一化和输出通道定义已与
[上游部署实现](https://github.com/SZURPVision/RuneDetectionModel/blob/master/infer/fivepoints_infer.cpp)
核对。更大的画面占比可能来自近距离拍摄或
更长焦距，不能只根据置信度推断实际物理距离。

## 配置与坐标

```yaml
rune:
  detector:
    confidence_threshold: 0.65
    keypoint_confidence_threshold: 0.5
    input_scale: 0.75
```

该配置把画面缩至 `480x360`，在 `640x480` 的网络输入中居中放置，左右各补
80 像素，上下各补 60 像素，补边值为 114。原图至模型的缩放为 `1/3`，解码时
先减去对应补边，再除以缩放系数，输出继续为原图坐标。输入缩放不修改相机
标定、能量机关物理尺寸或后续模块的像素尺度。

缩小时使用 `INTER_AREA`，减轻 LED 点阵的采样失真。`input_scale: 1.0` 保留
上游 `INTER_LINEAR` 满幅输入；缺省为 `1.0`，零、负数、大于 1 及非有限值
均拒绝加载。当前项目配置显式设为 `0.75`，实机、两个回放入口和 `rune_detect`
共用该参数。

## 对照方法

在原录像每 10 帧取一帧，共 185 帧；模型、CPU 设备、类别门限 0.65、五点门限
0.5 不变，仅改变输入处理。下表统计有候选通过类别和五关键点门限的帧：

| 输入处理 | 通过帧数 / 185 | 每帧最高类别分数的中位数 |
| --- | ---: | ---: |
| 原始满幅，线性采样 | 41 | 0.308 |
| 满幅，面积采样 | 67 | 0.551 |
| 缩小至 75%，线性采样 | 120 | 0.845 |
| 缩小至 75%，面积采样 | 151 | 0.938 |
| 先适配画布再缩小至 75%，两次线性采样 | 156 | 0.939 |

最终采用一次面积采样，避免多次 resize。另测得放大到能量机关所在区域未改善
这批样本，单纯调亮或调暗也未达到尺度补偿的效果。

这些数值是通过门限的帧数，**不是经过人工真值评估的召回率**。录像存在叶片
熄灯帧，不能要求所有帧都检出；误检、漏检和关键点误差仍应通过标注评估。
抽样实验主要用于区分输入尺度、采样与亮度的影响。

最终 C++ 实现完整回放 1843 帧，检出帧数从 390 提升到 **1534**，仍采用类别
门限 0.65 和五点门限 0.5；后续统计为 `no_detection=309`、`no_contour=1`、
`motion_not_ready=1533`。第二段无姿态录像的大符模式前 100 帧均检出目标，
按既有约定只运行检测。第一段第 1210 帧在满幅输入时最高类别分数约 0.007，
采用尺度补偿与面积采样后约 0.946，人工检查五点与靶板、R 标位置一致。

`rune_detector_smoke` 覆盖缺省输入、缩放后补边、原图五点坐标恢复、原图 NMS
距离及非法配置；两种张量布局均验证。实际回放仍使用原图执行轮廓提取与三维
重建。尺度改善不等于运动拟合已经稳定，`motion_not_ready` 需单独检查。
